## ✅ Ce qui tient

- **Sécurité du `rich-field`** : HTML initial `<img onerror>`, `<svg onload>`, `javascript:` dans `href`, `<style>`, `data-aster-variable` forgé avec `onclick` → `field.innerHTML` = `<p><img src="x"><a>x</a><span data-aster-variable="a" data-x="1" style="position:fixed">v</span></p>` (aucun `on*`, aucun `<svg>` / `<style>`, `href` retiré) ; le collage n'insère que `text/plain` (`<img src=x onerror=alert(1)>` collé → `<p>a&lt;img src=x onerror=alert(1)&gt;</p>`) ; aucun `innerHTML` du lot sans `sanitizeHeaderFooterHtml` (hôte, coupures, champ) ; hors les cas de R52-01, `read() → set() → read()` est stable (`<p>`, `<br>` interne, listes, tableaux, titres, `<b>`/`<i>`, `&nbsp;`).
- **Variantes et vue page** : `first` sur l'hôte et `first` / `even` / `default` sur chaque coupure selon la page (specs L52 relues), la clé de décoration porte `gap.page`, `pageCount` et le HTML des deux pages (`sectionSignature`) donc un changement de nombre de pages recrée les coupures ; `showHeadersFooters: false` ne pose rien dans la coupure ; trois `setPageView` puis `setPageView(false)` : 3 `addEventListener` / 3 `removeEventListener` pour `aster:page-view-last-page` et `aster:section-breaks-change`, `style` de l'hôte `null`, aucune classe `aster--page*` ; `setHostLastPage` ne dispatche que si la page change et le `ResizeObserver` ne regarde que la largeur (pas de boucle) ; police hostile `'"); background: url(x)'` → `--aster-page-font-family: "background: urlx"` (aucun `url(` dans le `style` de l'hôte), `1e12` / `-1` / `NaN` rejetés ; un `style="line-height: 2"` inline l'emporte sur le repli (règles sans `!important`).
- **Recherche** : `setContent`, `setHTML`, `undo`, requête sans correspondance, `clearSearch` ne provoquent aucun `scrollIntoView` supplémentaire (compteur figé à 1 après la requête initiale) ; 10 000 correspondances : `setSearchQuery` 159 ms, `nextMatch` 18 ms, une frappe 19 ms (jsdom) ; deux éditeurs : seule la correspondance de l'éditeur interrogé défile ; focus dans l'éditeur puis « suivant » sur le playground : un `scrollIntoView` (centré) puis un `scrollTop` de ProseMirror déjà satisfait (`scrollToSelection` tourne **après** les vues de plugin), pas de second saut visible ; une correspondance dans un en-tête de coupure n'est ni décorée ni cherchée (hors document) ; le bandeau : deux `Mod-f` → un seul bandeau, lecture seule → bandeau `hidden`, `destroy()` → `panel.remove()`.
- **Dialogue et i18n** : section intermédiaire éditée → premier niveau intact ; `sections` absent ou plus court que le corps → complété par le premier niveau puis recopie de la dernière ; `Object.keys(uiFr)` et `Object.keys(uiEn)` identiques ; le panneau est reconstruit à chaque ouverture (`createDropdown`), donc « vider puis Annuler » ne laisse rien.
