## ✅ Ce qui tient

- Idempotence stricte prouvée sur 44 formes, seules et cumulées, dans `p`, `h2`, `li`, `td`, `table` : `hr[data-section-break]` (numéro libre, en tête, final avec `TrailingNode`), `span[data-tab]` (`data-stop` en px converti, `0` → `0pt`, négatif / `1e9pt` / `100 000+` / texte → omis, contenu de l'atome ignoré, `style` d'un `span` hôte extrait en `textStyle`), `padding-<côté>` (px converti, sans bordure ignoré, négatif / `1e9` ignoré, ordre top/right/bottom/left rétabli, cellule avec `padding-top` **et** `padding` composite), `data-align` (`CENTER` normalisé, `javascript:` / vide / `align=""` HTML / `margin: 0 auto` → absent, ancienne forme `margin-left: auto; margin-right: auto` → `center`, seul → `right`), ordre `style` / `data-docx-style` / `data-align` sur `table`. Sérialiseur : `getHTML()` ne porte rien des NodeViews (`class`, `contenteditable`, variables CSS, `margin: 0 auto` restent dans le DOM d'édition).
- Commandes et clavier : `insertBreak` depuis une `NodeSelection` de table, une `CellSelection`, un document vide, un bloc de liste / cellule ; refus sur un saut sélectionné ; `removeBreak` par numéro, par sélection, curseur replacé ; Backspace / Delete sur un saut sélectionné ou adjacent ; undo / redo après `insertBreak` et après suppression clavier → numérotation exacte à chaque étape ; collage au curseur d'un HTML numéroté 7 → renuméroté 1 ; Tab dans titre, citation, liste (`sinkListItem`), tâche, cellule (navigation), liste **dans** une cellule (reste liste) ; Shift-Tab non intercepté ; Backspace avant / après une tabulation en début de paragraphe, dans un titre vide ; `getText()` → `a\tb\n\tc\nd\t`.
- Vue page : `1e9 mm`, `-1`, `NaN`, entrée `null` ou chaîne dans `sections`, `start` hostile (posé en attribut, échappé) → défauts A4 sur le `hr`, aucune exception ; saut 99 hors plage → repli dernière section ; `sections: []` → aucune variable sur les `hr`, hôte = premier niveau ; `getSectionLayout(0 | -1 | NaN | 1e9 | 2.5)` → repli. Écouteurs `aster:page-view-change` : 9 ajoutés / 9 retirés après `setPageView` ×2, suppression, undo, redo, `setHTML` ×3 et `destroy` (aucune fuite). Performance (jsdom, 1 000 sauts) : `setHTML` 101 ms, `getSections` 0,1 ms, frappe 1,2 ms (1,5 ms en vue page), `insertBreak` en tête (1 000 `setNodeMarkup` + 1 000 NodeViews) 186 ms, undo 143 ms, `setPageView` 22 ms, `getHTML` 19 ms.

## 📌 Dette proposée

1. Renumérotation par comparaison de suite plutôt que de compte (R41-01) et méta explicite sur `setContent` (R41-02) : deux tests à ajouter dans `section-break.spec.ts` (collage de plage, Ctrl+A + collage).
2. Sections vides (R41-03) : `afterCurrentBlock` sur `AllSelection`, paragraphe garanti avant un saut en tête et entre deux sauts ; proposer dans le contrat que « jamais de section vide » soit une invariante du corps, comme `TrailingNode`.
3. Tab dans un bloc de code (R41-04) : garde `spec.code` / `contentMatch` dans le keymap, `canRun` et, pour l'analyse, une règle contextuelle ou un `\t` texte dans `pre`.
4. Robustesse `sections` non tableau (R41-05), borne du numéro de section (R41-06), arguments de `removeBreak` (R41-07).
5. Sauts imbriqués (R41-08) : décision à acter (contexte d'analyse `doc/` ou nettoyage) ; sinon L42 doit ignorer explicitement un `hr[data-section-break]` hors premier niveau.
6. `spacePt` sur `between` (R41-09) : décision de contrat pour L42.
7. Découpage des deux fichiers > 400 lignes (R41-10).
8. À vérifier en navigateur (non prouvable en jsdom) : drag-drop d'un saut sélectionné (`draggable: false` n'empêche pas le drag d'une `NodeSelection`, cf. P2), ArrowLeft / ArrowRight à travers un `span.aster-tab` `contenteditable="false"`, Backspace natif sur la tabulation sans passer par le keymap (Android / IME).

**P2 — R41-01 déplacement en une transaction (forme d'un drop)**

```ts
editor.setHTML(TWO);

tr.insert(tr.doc.content.size, node.type.create(node.attrs));
```

**P3 — R41-02 Ctrl+A + collage**

