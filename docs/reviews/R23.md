## ✅ Ce qui tient

- **Sérialiseur verbatim** : document riche (titres, `text-align`, 10 marques, lien avec `&`/`"` dans `href`/`title`, `mark` multicolore, image `width`/`data-align`, table `colspan`/`colwidth`, task list, `ol type/start`, citation, bloc de code avec `<x>`, `hr`, variable, `&nbsp;`, `<br>`) : `serializeDocumentHtml` ≡ `tiptap.getHTML()` au `style` près (seules différences : `;` final et `rgb()` du CSSOM) ; aucun échappement d'attribut contournable (`docxStyle`, `shading`, `color`, `fontFamily`, `docxRunStyle` hostiles via `setJSON` → `&quot;` partout, `href="javascript:"` vidé par `link-safety`). 5 000 `<p>` stylés + table de 200 lignes : `setHTML` 1,8 s, verbatim 498 ms vs Tiptap 519 ms, `normalizeOutputHtml` +480 ms (préexistant), cache par identité de document 0 ms ; un sérialiseur par schéma en `WeakMap`.
- **Idempotence** : les 12 attributs seuls et cumulés, avec `text-align`, dans `<p>`, `<h2>`, cellule bordée/ombrée/alignée/paddée, `<li>` d'`<ol type="a" start="3" data-docx-num-id>` et d'`<ul data-bullet data-docx-num-id>` : identiques au caractère près ; marques de run cumulées (`color` + `font-family` + `letter-spacing` + `text-transform` + `data-docx-run-style`, `u`/`s` avec `text-decoration-style`, `span` avec raccourci `underline double` + couleur) ; tables avec `width` + bordures + `colwidth` sans `colgroup` ni `min-width` en sortie ; image `width`/`height`. Valeurs hostiles : `1e9pt`, `NaNpt`, `expression(`, `url(javascript:)`, `rgb(300,-1,0)`, `line-height: -2`, `margin: 1pt 2pt 3pt 4pt 5pt`, `;` dans `url()` → ignorées proprement ou normalisées (`#FFF` → `#ffffff`, `6.125pt` → `6.13pt`, `-0pt` → `0pt`, 22 chiffres → idempotent), `getText()` et `variables: 'resolve'` inchangés.
- **Commandes** : `null` efface, fusion conserve, `{}`/attributs inconnus/`attrs: ['bogus']` refusés, second appel identique → `false`, lecture seule filtrée, `canRun` faux sur `hr`, image, bloc de code, `AllSelection` applique partout ; `text.setCaps { caps: 'ALL' }` et `pt: NaN` refusés ; format painter copie bien la mise en page de paragraphe ; sanitiseur : `on*`, `<script>`, `<svg>`, `<math>`, `<form>`, `<noembed>`/`<title>` (mXSS), `xlink:href`, `javascript&#58;`, `data:text/html`, `expression(`, `-moz-binding` tous neutralisés ; vue page : `setPageView` répété sans doublon, `style` préexistant de l'hôte conservé au retrait, `destroy` propre, `B5`/`LANDSCAPE`/`NaN`/négatif → défauts.

## 💳 Dette proposée

1. `//evil.example/x` (URL relative au protocole) est accepté par `isSafeUrl` (`startsWith('/')`) : à restreindre à `/` simple, à documenter sinon.
2. `target="_blank"` sans `rel` dans un en-tête : poser `rel="noopener noreferrer"` comme `link-safety`.
3. `parseStyleDeclarations` coupe sur `;` même dans `url()`/guillemets : réutiliser un découpage à profondeur (comme `splitStyleDeclarations` de Tiptap) avant que `font-family: "a;b"` ne devienne un attribut du contrat.
4. `index.ts` exporte 47 blocs dont des internes (`renderRawSpec`, `createRawStyleSerializer`, `AsterTableView`, `tableLayoutHtmlAttributes`…) : figer ce qui est public avant la 1.0.
5. `margin: 6pt 0 6pt 36pt` (raccourci) n'est pas lu : utile pour le collage HTML hors Word.
