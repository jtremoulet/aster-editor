# 🎨 @aster-editor/ui

> Toolbar vanilla, composants accessibles (menus, dialogues, recherche, vue source, plein écran, caractères spéciaux, impression, variables, bulles contextuelles, menu `/`, sommaire, reproduction de mise en forme, et depuis la session 3 interligne, espacement, retraits, bordures et fond de paragraphe, casse, style de souligné, mise en page ; depuis la session 5 en-têtes et pieds éditables par section dans le dialogue « Mise en page » et recherche en bandeau), 85 icônes SVG, thèmes CSS et vue page pour Aster Editor. Aucun framework, aucune logique d'édition : tout passe par le registre de commandes du core.

## 📦 Installation

```bash
npm install @aster-editor/core @aster-editor/ui
```

Les thèmes sont servis via l'export `@aster-editor/ui/themes/*.css`.

## 🚀 `createAster`

Point d'entrée recommandé : monte thème, toolbar, menu contextuel de table, dialogue et suggestion de variables, bulles de lien et d'image, menu `/` et éditeur dans un hôte.

```ts
import '@aster-editor/ui/themes/aster.css';
import { createAster } from '@aster-editor/ui';

const instance = createAster(document.querySelector<HTMLElement>('#editor')!, {
  toolbar: 'standard',
  theme: 'light',
  locale: 'fr',
  content: '<p>Bonjour</p>',
});

instance.editor.on('change', ({ editor }) => console.log(editor.getHTML()));
instance.setTheme('night');
instance.toggleSource(); // vue source HTML
instance.setFullscreen(true);
instance.destroy();
```

```ts
function createAster(host: HTMLElement, options?: AsterUiOptions): AsterInstance;
```

### Options (`AsterUiOptions`)

Toutes les `AsterOptions` du core (section « Options » du [README core](../core/README.md)) sauf `element`, plus :

| Champ                | Type                         | Défaut       | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------- | ---------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `toolbar`            | `ToolbarConfig`              | `'standard'` | Preset, liste de groupes, ou `false` pour aucune toolbar.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `theme`              | `AsterTheme`                 | `'light'`    | `'light'`, `'night'` ou le nom d'un thème custom (`data-theme`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `variableSuggestion` | `boolean`                    | `true`       | Menu de suggestion déclenché par `{{` dans le contenu (variables du magasin, création si autorisée). Monté dès que le core expose `variable.insert`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `linkBubble`         | `boolean`                    | `true`       | Bulle sous un lien (URL, modifier inline, supprimer). Montée dès que le core expose `link.set`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `imageBubble`        | `boolean`                    | `true`       | Bulle au-dessus d'une image sélectionnée (alignement, largeur 25 / 50 / 100 %, modifier, supprimer). Montée dès que le core expose `image.setAttributes`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `slashMenu`          | `boolean`                    | `true`       | Menu de blocs déclenché par `/` en début de bloc.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `pageView`           | `boolean \| PageViewOptions` | `false`      | Vue page (session 3) : transmise telle quelle au core (`AsterOptions.pageView`), qui pose `aster--page-view` et les variables `--aster-page-*` sur l'hôte ; `themes/page.css` rend alors la feuille, les marges, les en-têtes / pieds (sur chaque page depuis la session 5, bande minimale d'une ligne), les coupures de la pagination approximative, depuis la session 4 les sauts et coupures de section, et depuis la session 5 la police et les défauts de paragraphe du document (`--aster-page-font-*`, `--aster-page-default-*`, classe `aster--page-defaults`) sur les blocs sans valeur propre. `tabKey` du core passe aussi par ces options. |

```ts
const instance = createAster(host, {
  toolbar: 'full',
  variableSuggestion: true, // menu `{{`
  linkBubble: true,
  imageBubble: true,
  slashMenu: true,
  pageView: { layout: { page: { size: 'A4', orientation: 'portrait' } }, pagination: true },
  variables: { variables: [{ name: 'client.nom', label: 'Client' }] },
});
```

### Résultat (`AsterInstance`)

| Membre                 | Type              | Rôle                                                                                                                                                                                                                                                       |
| ---------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `editor`               | `AsterEditor`     | L'éditeur du core.                                                                                                                                                                                                                                         |
| `toolbar`              | `Toolbar \| null` | `null` si `toolbar: false`.                                                                                                                                                                                                                                |
| `element`              | `HTMLElement`     | Racine `.aster[data-theme]` créée dans l'hôte.                                                                                                                                                                                                             |
| `setTheme(theme)`      | `void`            | Change `data-theme` à chaud.                                                                                                                                                                                                                               |
| `toggleSource()`       | `void`            | Bascule entre l'éditeur et la vue source HTML (`<textarea class="aster-source">`). Pendant la vue source, l'éditeur est en lecture seule et la toolbar désactivée ; le retour applique le HTML modifié. Sans effet si l'éditeur est déjà en lecture seule. |
| `isSourceView()`       | `boolean`         |                                                                                                                                                                                                                                                            |
| `setFullscreen(value)` | `void`            | Ajoute ou retire `aster--fullscreen` sur `.aster` (position fixe plein écran). `Échap` quitte.                                                                                                                                                             |
| `isFullscreen()`       | `boolean`         |                                                                                                                                                                                                                                                            |
| `destroy()`            | `void`            | Quitte le plein écran et la vue source, détruit menu `/`, bulles, suggestion et dialogue de variables, menu contextuel, toolbar et éditeur, retire la racine. Idempotent.                                                                                  |

`createAster` monte aussi, même sans toolbar : le **menu contextuel de table** (clic droit dans un tableau) dès que le core expose `table.delete` ; le **dialogue de puce** (double-clic sur une variable, `aster:variable-edit`) et la **suggestion `{{`** dès qu'il expose `variable.insert` ; les **bulles** de lien et d'image ; le **menu `/`**, qui n'ouvre les dialogues Image et Lien que si la toolbar existe (il clique leur déclencheur).

Structure DOM produite :

```html
<div class="aster" data-theme="light">
  <div class="aster__toolbar"><div class="aster-toolbar" role="toolbar">…</div></div>
  <div class="aster__content">
    <div class="aster-content"><div class="ProseMirror">…</div></div>
  </div>
</div>
```

## 🧰 `createToolbar`

Pour monter la toolbar toi-même, sur un éditeur créé par `createEditor` :

```ts
function createToolbar(
  editor: AsterEditor,
  container: HTMLElement,
  config?: ToolbarConfig,
): Toolbar;
```

```ts
import { createEditor } from '@aster-editor/core';
import { createToolbar } from '@aster-editor/ui';

const editor = createEditor({ element: contentHost });
const toolbar = createToolbar(editor, toolbarHost, 'minimal');
toolbar.update(); // resynchronise à la main (automatique sur selectionChange, readOnlyChange, localeChange)
toolbar.destroy();
```

`createToolbar` enregistre aussi les chaînes UI (`registerUiTranslations`) sur l'éditeur. Les items dont la commande n'existe pas sont ignorés avec un `console.warn`. Un preset inconnu tombe sur `standard` avec un avertissement.

### Config déclarative (`ToolbarConfig`)

`ToolbarConfig = 'full' | 'standard' | 'minimal' | readonly ToolbarGroup[] | false`. Un groupe est un tableau d'items séparé visuellement des autres. Un item est :

| Forme                                                                      | Rendu                                                                   |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `'bold'` (chaîne = `CommandId`)                                            | Bouton de commande, icône et libellé par convention.                    |
| `{ command, args?, labelKey?, icon? }` (`ToolbarButtonItem`)               | Bouton avec arguments fixes, libellé et icône surchargés.               |
| `{ type: 'dropdown', id, labelKey, icon?, items }` (`ToolbarDropdownItem`) | Menu déroulant générique dont chaque entrée est un `ToolbarButtonItem`. |
| `{ type: 'widget', widget }` (`ToolbarWidgetItem`)                         | Composant spécialisé fourni par `ui`, voir ci-dessous.                  |

```ts
import type { ToolbarGroup } from '@aster-editor/core';
import { createAster } from '@aster-editor/ui';

const toolbar: readonly ToolbarGroup[] = [
  ['undo', 'redo'],
  [{ type: 'widget', widget: 'heading' }],
  ['bold', 'italic', { command: 'highlight', icon: 'text-color' }],
  [
    {
      type: 'dropdown',
      id: 'titles',
      labelKey: 'command.heading',
      icon: 'heading',
      items: [
        { command: 'heading', args: { level: 2 }, labelKey: 'command.heading.level' },
        { command: 'heading', args: { level: 3 } },
        { command: 'paragraph' },
      ],
    },
  ],
  [
    { type: 'widget', widget: 'link' },
    { type: 'widget', widget: 'table' },
  ],
  [
    { type: 'widget', widget: 'search' },
    { type: 'widget', widget: 'specialChars' },
    { type: 'widget', widget: 'print' },
    { type: 'widget', widget: 'source' },
    { type: 'widget', widget: 'fullscreen' },
  ],
];

createAster(host, { toolbar });
```

**Éditeur riche minimal des en-têtes** (`components/rich-field.ts` + `rich-field-html.ts`, session 5 ; non exportés du paquet, testés par `rich-field.spec.ts` et `page-layout-headers.spec.ts`) : un `div.aster-page-layout__rich[contenteditable][role="textbox"][aria-multiline]` sans Tiptap (le dialogue est vanilla), libellé par un `<label>` qui le focalise au clic. Exemple de dropdown maison branché sur une commande custom :

```ts
import { createDropdown, createMenuItem } from '@aster-editor/ui';

const stamp = createDropdown({
  editor,
  labelKey: 'command.insertDate',
  icon: 'horizontal-rule',
  renderPanel: (panel, dropdown) => {
    for (const format of ['short', 'long'] as const) {
      panel.append(
        createMenuItem({
          text: format,
          onSelect: () => {
            editor.commands.run('insertDate', { format });
            dropdown.close(false);
            editor.focus();
          },
        }),
      );
    }
  },
});
toolbar.element.append(stamp.element);
```

## 🖼️ Icônes

Jeu maison MIT, SVG inline 20 × 20 en `currentColor`, injecté dans `.aster-toolbar__icon`.

| Export                   | Rôle                                                                       |
| ------------------------ | -------------------------------------------------------------------------- |
| `getIcon(name)`          | SVG de l'icône. Nom inconnu → icône « ? » visible, jamais une chaîne vide. |
| `hasIcon(name)`          | Vrai si le nom existe dans le jeu (`constructor`, `toString`… → `false`).  |
| `iconNameForCommand(id)` | Convention : `table.insert` → `table-insert`, `alignLeft` → `align-left`.  |
| `ICON_NAMES`             | Liste des 85 noms disponibles.                                             |

Noms : une icône par commande standard (`bold`, `heading`, `heading-1` … `heading-6`, `bullet-list`, `table-insert`, `link-set`, `text-color`, `variable-insert`, `variable-remove`, `paragraph-set-layout`, `paragraph-unset-layout`, `undo`…), `chevron-down`, `check`, `close`, `none`, celles des widgets 0.3.0 (`search`, `search-previous`, `search-next`, `source`, `fullscreen`, `fullscreen-exit`, `special-chars`, `print`), celles de 0.4.0 (`variable`, `edit`, `trash`, `slash`, `outline`, `format-painter`, `page-break`) et les huit de la session 3 : `line-spacing`, `paragraph-spacing`, `indent-increase`, `indent-decrease`, `paragraph-borders`, `caps`, `underline-style`, `page-layout`. L'icône `ordered-list` a été redessinée (chiffres lisibles, test géométrique dans `icons/index.spec.ts`).

Résolution de l'icône d'un bouton : `item.icon` explicite → `command.icon` déclaré → convention `iconNameForCommand(id)` → repli. Chaque candidat passe par `hasIcon` : un `item.icon` inconnu ne masque pas l'icône de la commande. Pour une commande custom, le plus simple est de réutiliser un nom existant (`icon: 'horizontal-rule'`). Les commandes `search.*` n'ont pas d'icône par convention (`search-open` n'existe pas) : passe par le widget `search` plutôt que par un bouton `'search.open'` nu.

**Ajouter une icône** : le jeu est fermé, il n'y a pas d'API d'enregistrement. Deux options : choisir un nom du jeu, ou remplacer le SVG après montage :

```ts
const button = toolbar.element.querySelector<HTMLElement>('[data-command="insertDate"]');
const icon = button?.querySelector<HTMLElement>('.aster-toolbar__icon');
if (icon) icon.innerHTML = MY_SVG; // SVG 20×20, fill ou stroke en currentColor
```

## ♿ Accessibilité

- Toolbar : `role="toolbar"` avec `aria-label` traduit, groupes `role="group"`.
- Boutons : `aria-label` (libellé seul), `title` (libellé + raccourci), `disabled` + `aria-disabled`. `aria-pressed` n'est posé que sur les boutons à bascule, c'est-à-dire les commandes qui déclarent `isActive` (`bold`, `alignLeft`…) et les widgets `source` / `fullscreen` ; `undo`, `horizontalRule` ou une commande custom sans `isActive` n'en ont pas. Le `mousedown` des boutons ne vole pas le focus à l'éditeur.
- Navigation : **roving tabindex**, un seul bouton tabbable à la fois. `←` / `→` entre les boutons, `Home` / `End`, les boutons désactivés sont sautés.
- Dropdowns : `aria-haspopup`, `aria-expanded` ; `↓` ouvre, `Échap` ferme et rend le focus au déclencheur, un second clic sur le déclencheur aussi, clic extérieur ou focus sorti du dropdown (`focusout`, `Tab`) ferment ; dans un panneau `menu`, `↑` / `↓` entre les `menuitem`, les entrées des commandes à état sont des `menuitemradio` avec `aria-checked`, les autres de simples `menuitem`. Un panneau qui déborderait à droite du viewport reçoit `aster-dropdown__panel--flip` (aligné sur le bord droit du déclencheur). Si le dropdown se désactive alors que son panneau a le focus (lecture seule, vue source), le focus revient à l'éditeur.
- Dialogues (lien, image, recherche, caractères spéciaux, espacement, bordures et fond, mise en page, interligne personnalisé) : `role="dialog"` avec `aria-label`, premier champ focalisé à l'ouverture, `Entrée` valide, erreurs en `role="alert"` + `aria-invalid`. Dans la recherche, `Entrée` / `Shift+Entrée` naviguent, `Échap` efface le surlignage comme « Fermer », le compteur est en `aria-live="polite"`. Les groupes de champs des dialogues de mise en page sont des `role="group"` / `radiogroup` nommés (orientation, marges, interligne), chaque sélecteur de bordure porte un `aria-label` « côté – propriété » (l'en-tête de colonne est visuellement suffisant, le libellé reste pour les lecteurs d'écran) ; `pageLayout` est un déclencheur `aria-pressed` quand la vue page est active ; sa section « En-tête et pied » est un `role="group"` nommé, chaque champ riche un `role="textbox"` `aria-multiline` relié à son libellé par `aria-labelledby` (un `<label for>` ne focalise pas un `div`, le libellé le fait au clic), les champs `first` / `even` masqués portent `hidden`. Le bandeau de recherche (session 5) est un `role="dialog"` dans le flux, relié au déclencheur par `aria-controls` / `aria-expanded`, et garde le focus dans son champ quand le document défile. Les menus `lineSpacing`, `caps` et `underlineStyle` sont des `menu` à `menuitemradio` cochés selon l'état du bloc ou de la marque.
- Caractères spéciaux : onglets `role="tablist"` / `tab` (`aria-selected`, `←` / `→`, `Home` / `End`), grille parcourue aux quatre flèches, chaque cellule a un `aria-label` « Insérer … ».
- Grille de table : chaque cellule a un `aria-label` « Tableau r × c », taille annoncée en `aria-live="polite"`, navigation `←` / `→` dans la ligne et `↑` / `↓` entre les lignes (`↓` depuis la dernière ligne passe aux actions `table.*`).
- Menu contextuel de table : ouvert au clic droit, ramené dans le viewport, fermé à `Échap`, au clic extérieur, en lecture seule et quand la sélection quitte le tableau ; focus rendu à l'éditeur à la fermeture.
- Vue source : `<textarea aria-label>` (`ui.source.label`), `spellcheck="false"`, focalisé à l'entrée ; le reste de la toolbar est grisé par la lecture seule, le bouton `source` reste actif.
- Plein écran : `Échap` quitte, écouté en phase de capture sur `.aster` (ProseMirror consomme la touche sinon) ; un panneau ouvert (`OPEN_PANEL_SELECTORS` : dropdown, menu contextuel, suggestion `{{`, dialogue de puce) est fermé en priorité.
- Suggestion `{{` et menu `/` : panneaux `role="listbox"` d'options `role="option"` ; tant qu'ils sont ouverts, le contenteditable porte `aria-controls`, `aria-expanded` et `aria-activedescendant` (option surlignée), tout est retiré à la fermeture. `↑` / `↓` déplacent, `Entrée` valide (et `Tab` dans le menu `/`), `Échap` ferme, clic extérieur aussi ; les boutons ne volent pas le focus. Sans résultat, le menu `/` garde un message « aucun bloc » et ne consomme pas `Entrée`.
- Dialogue de puce : `role="dialog"` ancré sous la puce, champs libellé et valeur, premier champ focalisé, `Entrée` applique, `Échap` ferme et rend le focus à l'éditeur ; retraduit sur `localeChange` sans perdre la saisie.
- Bulles de lien et d'image : rien n'est focalisé à l'ouverture, seule une saisie explicite dans le champ d'URL prend le focus ; bouton d'alignement courant en `aria-pressed` ; cachées en lecture seule et en vue source.
- Widget `variable` : entrées `menuitem` avec `title` = description ; formulaire « Nouvelle variable » avec erreur `role="alert"` (nom invalide ou non déclaré).
- Pastilles de couleur : `aria-label` et `title` traduits, `aria-checked` sur la couleur courante.
- Impression : la fenêtre reçoit `lang` de la locale courante et un `<title>` traduit.
- Focus visible via `--aster-focus-ring`, `prefers-reduced-motion` respecté.
